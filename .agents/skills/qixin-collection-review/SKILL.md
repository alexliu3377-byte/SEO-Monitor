读取仓库 AGENTS.md、CLAUDE.md 和 [共享审核规范](../../../docs/REVIEW_AND_RELEASE.md)。默认只读检查用户指定的代码或运行证据；生产访问按已有授权范围处理，缺失访问能力时继续代码检查并标注线上未验证。

先定位 GitHub Actions 调度、Windows 执行器/计划任务和实际运行目录，区分主仓库与独立 trend-collector-worker。旧电脑是否参与不能从历史文档推断。核对工作流版本、UTC 与 MYT 时间、条件开关、并发、锁及重试；不触发 workflow、补抓或转写，不重注册任务。

从当前配置确认每个来源的自动/手动模式与预期周期，再评估新鲜度。小红书历史上为手动触发，必须以当前配置复核，不能仅因数据旧就判定定时任务故障。将源资料日期、发现时间、采集时间、缓存计算时间分开；任务 success、processing_complete 和资料完整不是同一件事。

核对 lib/crawl-rules.ts 与实际写入、触发、重试、去重和保留期；涉及镜像逻辑时读取独立 Worker 对应实现。检查未知日期保持空值、跨 MYT 午夜和跨年解析、链接身份、重复抓取、七日展示窗口与月度归档保护。空值、零值、被阻止、来源缺失和过期缓存分别报告，不补零、不把未知日期标为今天。

如获授权读取线上数据，使用有范围的只读元数据查询，选择必要字段并限定行数；记录来源、日期、任务/提交与观察时间，不输出正文、账号、Cookie 或密钥。来源页面仅查看允许的公开资料，不绕过登录、付费或验证码。

结果按“来源/任务、预期周期、实际证据、确认或待验证、影响、下一步”列出。故障建议给出最小复现或待取日志，不把重新采集当成默认验证。修改开发副本不代表运行副本更新。优先级与汇总遵循 [综合审核入口](../qixin-review/SKILL.md)，无需递归执行它。
