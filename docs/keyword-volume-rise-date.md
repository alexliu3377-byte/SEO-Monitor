# 搜索量上涨：发现上涨日期

任务工作台、热词雷达的日期列统一为“发现上涨”，不是最新采集日。

- 数据库逐行比较实际写入前后的搜索量。数值增加时记录当天的马来西亚日期；保持、下降、排名方向改变、分类修改均不刷新日期。
- 同一天重复采集相同数值、多个站点对相同词的相同数值重复写入，不会抹掉原上涨日期。旧资料日期的延迟写入不能将其标为今天上涨。
- 首次得到一个搜索量，没有之前的数值可比较，不能认定上涨。
- 累计上涨仍为当前搜索量减追踪起点，不改变基线或涨幅算法。
- `last_volume_increase_date`由数据库触发器维护，采集器不提交日期，避免多个抓取进程用各自旧快照计算出假日期。
- 历史日期没有可靠记录时保持null，页面显示“未记录”。词条和累计上涨仍保留在全部日期中，已知日期筛选只匹配真实记录。
- 详情将“采集”与“发现上涨”分开；全局/分组旧缓存的`last_date`只迁入`volumeDate`，不能当成上涨日期使用。

示例：16日观察到100→120，日期记16日；17日再次抓到120，仍为16日；18日观察到120→130，才改为18日。

## 上线顺序

1. 仅应用`supabase/migrations/20261016_keyword_volume_rise_date.sql`，不要连同其它未上线迁移一起推送。它新增可空字段及触发器，不回填、不删除词库、不改累计数值。
2. 部署代码。兼容旧采集器，无需改GitHub Runner、抓取时间或环境配置。
3. 下次有效上涨会记录日期；下次正常全局/分组缓存刷新会带出新字段。旧缓存读取也会清除原来冒充上涨日期的采集日，因此不能用旧缓存填补未知历史。
