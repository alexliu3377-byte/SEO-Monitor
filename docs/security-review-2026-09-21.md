# 网站安全审查（2026-09-21）

## 结论

当前系统已有较好的基础防护，暂未发现可直接匿名读取后台资料的高危漏洞。本轮先完成三项低风险、可立即上线的加固：跨站写请求拦截、GitHub Actions 输入隔离，以及 API 禁止缓存与补充响应头。

本轮没有让自动化渗透工具直接攻击生产环境。Strix 会主动尝试利用漏洞，不只是读取代码；应先在 Vercel Preview 或独立测试环境中限定域名、账号和速率后运行。

## 已验证

- `npm audit --omit=dev`：生产依赖已知漏洞为 0。
- 未发现真实密钥、`.env`、私钥文件被 Git 跟踪。
- 线上根路径已经启用 CSP、HSTS、禁止 iframe、MIME 嗅探保护和严格来源策略。
- 未登录访问用户管理、站点管理、应用更新、定时抓取和趋势采集配置接口均返回 401。
- 外部抓取 URL 已限制为 HTTP/HTTPS 标准端口，并阻止私网、回环、保留地址以及跳转到私网，降低 SSRF 风险。
- GitHub Actions 使用的第三方 Action 已固定到具体 commit SHA。

## 本轮修复

### 1. 跨站写请求保护

对已经登录的浏览器发往 API 的 POST、PUT、PATCH、DELETE 请求统一检查 `Origin` 和 `Sec-Fetch-Site`，拒绝跨站请求。服务端采集任务仍使用独立 Bearer 密钥，不受浏览器检查影响。

### 2. GitHub Actions 命令注入保护

`onboard-site.yml` 原先把手动输入直接插入 shell 命令。现在统一通过环境变量传入并加引号，域名采用白名单格式，补抓天数限制为 1–30，同时把工作流权限固定为只读仓库内容。

### 3. 敏感响应缓存保护

所有 `/api/*` 响应增加 `private, no-store`，避免后台资料进入浏览器或中间共享缓存；同时增加同源资源策略和禁止旧式跨域策略文件响应头。

## 后续建议

1. 为 Vercel 建立独立 Preview 测试环境，使用测试 Supabase 项目或脱敏数据库。
2. 主动渗透工具目前保持停用；若以后重新评估，只能测试 Preview 域名和测试账号，并排除删除账号、删除站点、触发批量抓取和 Supabase 管理接口。
3. 人工审查继续优先检查认证绕过、越权、IDOR、CSRF、XSS、SSRF，不进行高并发或拒绝服务测试。
4. 登录限流已改为 Supabase 数据库全局计数，按 IP 与 IP＋用户名双层限制；数据库只保存 HMAC 摘要。若以后开放给更多外部用户，仍建议再增加 Vercel/Cloudflare WAF 边缘限流。
5. 每次增加高权限 API 时，继续同时检查服务端角色和资源归属，不能只依赖左侧菜单隐藏。
