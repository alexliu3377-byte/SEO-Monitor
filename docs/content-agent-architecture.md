# 奇心内容 Agent：架构选择与分阶段接入

记录日期：2026-10-26。范围：现有奇心资料与业务规则为核心；不恢复已删除的页面设计系统。

## 本批实现与未完成事项

- 已实现、待部署：负责人只读导出选中的内容发现记录及已保存正文／字幕，本地资料包导入，来源与日期保留，摘要不能单独支撑草稿。
- 沿用本地原型：受限工具、任务与事件记录、手动确认规则、人工审核。人工通过不触发发布。
- 尚未实现：团队任务领取、持久化断点恢复、全天调度、百度实时下拉采集、自动补采、自动发布、语义事实核验。
- LangGraph JS、Mastra、Crawlee 已在被 Git 忽略的隔离目录做首轮离线试验，正式项目尚未接入；Promptfoo 暂放。结果见下方验证记录，不得把离线流程测试当成真实模型质量评测或采集问题已经修好。

## 取舍

| 层 | 方案 | 选择与接入边界 |
| --- | --- | --- |
| 资料与权限 | 参考 Craft Agents | 采用资料源、凭证、权限分离的思路；实现奇心自己的工具接口，不搬入 Electron 应用或凭证实现。 |
| 执行流程 | LangGraph JS 优先候选 | 评估检查点、人工中断和恢复；节点调用奇心工具，不让框架自由访问生产数据库。 |
| 执行流程备选 | Mastra | TypeScript 工作流与人工审核是合适的备选；核对企业目录许可。不要同时引入两套运行时。 |
| 采集 | Crawlee 单来源试点 | 沿用 Playwright／Cheerio 解析，试验队列、重试和会话生命周期。不立即替换全部采集器。 |
| 内容评测 | Promptfoo | 后续接离线结果回放和固定样本；先做确定性规则，再决定是否需要付费模型评分。 |
| 资料与审核主库 | 奇心现有 Supabase | 仍为内容、分组、提交及审核事实来源。暂不新增向量库、Redis 或第二套任务管理产品。 |

2026-10-26 只读查询 npm 元数据：LangGraph JS 1.5.2（Node >=18）、Mastra core 1.79.0（Node >=22.13）、Crawlee 3.18.2（Node >=16）、Promptfoo 0.125.1（Node >=22.22）。这是候选版本与运行要求，不是已安装版本或性能结论；真正集成时重新核对锁定版本、许可及依赖审计。

## 先稳定工具协议，再替换执行底座

流程：选题 → 受控读取奇心资料 → 明确资料缺口 → 经允许补采 → 来源资料包 → 草稿 → 质量检查 → 人工审核。

当前只开放 memory.search、materials.list、materials.read。资料来源和已确认偏好分开：编辑规则可以长期使用；版本、功能、收费、排名、搜索量需要日期和证据。资料中的文字无权扩大工具权限。

本批资料读取限定内容发现记录，并进一步收紧为项目负责人导出；不读取成员的私有提交。将来增加分组词、任务提交或站点资料时，必须在服务器重新验证账号、分组成员关系、可见站点和字段权限。不能让模型传入 user_id 或 group_id 就获得资料，也不能把这次负责人特例直接复用为团队授权。

每份资料携带项目记录编号、公开来源链接、发布时间、首次采集时间、正文更新时间、摘要／正文／人工字幕／自动字幕／本地识别类型、节选标记。AI 建议的标题和词不能标作真实百度下拉或真实搜索量。

## LangGraph JS 与 Mastra 的验收比较

首轮结果见 [采集与框架验证记录](collection-validation-2026-10-26.md)。两者都通过了同进程暂停／恢复、失败步骤重试及重复恢复检查；持久化和进程重启恢复尚未测试。

优先做独立、无生产写入的概念验证，两者使用相同工具与测试任务：

1. 读取两份指定资料，引用编号必须对应实际读取记录。
2. 人工审核时释放运行进程；恢复后保持同一任务及资料版本。
3. 第二步骤失败后恢复，不重新执行已完成的外部写入。
4. 杀进程再启动后能识别旧运行、锁和未完成动作，不能双重领取。
5. 超时、额度不足、权限拒绝应有明确结束状态，不能无限重试。
6. 对比新增依赖、常驻内存、启动开销、检查点读写、维护复杂度。

特别注意：LangGraph 中断后的节点可能重新执行，因此保存草稿、发起补采、写审核记录等操作仍要有幂等标识。检查点不能替代业务幂等与权限检查。持久化方案必须有独立表／命名空间、保留期限和读取权限；避免再次增加 Supabase 的无界写入和磁盘压力。

选择标准是上述实测结果，不是 Star 数。未完成概念验证前，不承诺某框架在奇心更快或更省钱；也不将现有本地事件日志称为断点恢复。

## Crawlee 单来源试点

先用已保存、脱敏的页面快照验证解析一致性，不为比较而反复访问第三方站点。然后挑一个维护成本较高的现有来源，由负责人确认后小流量试跑：

- 沿用当前字段、发布日期判断、链接校验与入库去重。
- 以“来源＋规范化链接＋任务日期／采集目的”定义请求标识；不能只按 URL 永久去重，导致以后更新永远不抓。
- 单域低并发、有限重试、退避；认证失效、验证码、403／429进入明确阻塞状态。
- 不因换框架而自动购买代理、切换出口 IP 或突破访问权限。
- 保持 GitHub／采集电脑原有分工及调度，验证无碰撞后再切换。

## Promptfoo 与质量样本

2026-10-26 负责人决定：Promptfoo 暂放。本轮优先核查现有采集资料，以真实异常比较工作流与采集器，不接入 Promptfoo，不进行模型评分。

第一轮固定样本应来自人工明确选择、脱敏的奇心资料；不能把人工编造样例的通过率当成真实模型准确率。

确定性检查：输出结构、实际读取来源、摘要限制、标题规范、空正文、长度上限、敏感信息、重复调用与非法工具。对原文引述可检验是否存在于来源；这仍不能证明转写本身正确。

人工／语义检查：资料是否属于同一产品、功能与版本是否真实、教程步骤是否有依据、同产品不同标题是否对应不同用户需求、文章间是否只是换词。规则应版本化，保留输入资料、输出、模型／提示词版本与审核理由。模型评分会产生独立推理开销，不默认开启。

## 运行与费用边界

Vercel 只处理短请求、权限检查和少量选中资料，不承载浏览器、长时间模型循环或全天轮询。重任务仍放本地电脑或合适 Worker；不因此自动升级任何套餐。

本机模型调用仍沿用个人明确发起的试用，不向团队开放共享账号。没有新增收费 API、云服务、代理或常驻调度。开源许可、推理费用与托管资源是不同问题，接入时分别确认。
