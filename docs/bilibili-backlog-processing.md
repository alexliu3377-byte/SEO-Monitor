# B站积压文字处理（2026-10-19）

## 本次核查

核查时共 198 条：64 条完成、130 条排队、1 条过期 processing、2 条失败、1 条受限。
GitHub 采集任务成功不代表随后的文字转换全部成功：采集器把转写失败作为警告，采集工作流仍可能显示绿色。

- 三条异常在日志里出现过结果接口 HTTP 400，分别在读取字幕或本地识别之后；其中一条后来保存为普通失败，一条仍是过期 processing。
- 原始被拒绝结果已经随旧临时目录清除，不能据此断定具体哪个字段有问题。新增安全字段错误码及本地拒绝结果备份，以便下一次实际定位。
- 已离线复现读取 Python stdout 的 UTF-8 分块缺陷：旧 `String(Buffer)` 逐块解码会在中文字跨块时产生替换字符，同一结果里的全文和分段可能因边界不同而不相等。改为流式 `StringDecoder` 并测试所有字节切分位置。确认这是代码缺陷，但无法证明旧三条全部由此引起。
- 另一条因无可用字幕且视频超过本地识别默认 30 分钟上限而受限。不是已证实的付费/登录问题，也不是整轮运行时间限制。

## 改动边界

- 服务端验证仍拒绝非法时间、超长或空文字、文字与段落不一致；只增加固定错误码，不回显文字或密钥。
- Python 对齐 JavaScript 首尾空白、UTF-16 字数及时间校验；不猜改内容、不截断后冒充完整转写。
- 单条结果被 400/413 拒绝时，采集电脑先保存不含租约、Cookie 或配置密钥的结果备份，再确认保存该条失败状态，才继续下一条。
- 401/403/409/429/5xx、网络故障或失败状态也无法保存时仍停止，不冒充入库成功。
- 新迁移只修正今后的租约过期说明，并将清理限制在本次请求来源；不清零重试次数、不覆盖已完成文字、不批量重排异常资料。
- 小黑盒文字暂停；新的全天任务只消费 B站，小红书不会被自动纳入。

## 采集电脑设置

独立采集器仓库增加 `scripts/register-bilibili-backlog-task.ps1`。须先发布两个仓库的更新，再在原采集电脑原目录更新并安装；不能仅更新后台便认为远程任务已生效。

新任务 `SEO-Content-Text-Bilibili-Backlog` 每 30 分钟检查一次；首轮约两分钟后。每轮不再限制 10/50 条，但 25 分钟领取预算到达后不再领取新视频，当前视频仍允许在原有单条超时内完成。空队列直接结束。

当前 Windows 用户必须保持登录、电脑开机不休眠；断开远程桌面不等于注销。任务不依赖 PowerShell 窗口或 GitHub runner 在线。

串行处理、全局处理锁和任务 IgnoreNew 防止模型重叠。浏览器读取 Cookie 后释放来源锁，再开始音频识别，避免长时间占用采集浏览器。其它任务占用来源锁时不领取资料、不扣尝试次数。未关闭的手动浏览器仍可能导致启动失败，需要人工关闭。

遇到登录/验证/专用浏览器异常，在确认保存受限状态后额外暂停该来源 24 小时，跨进程生效；人工恢复登录并关闭专用窗口后，才可显式使用 `-ResumeAccess` 解除来源暂停。此开关不重置数据库中单条三次上限，也不绕过平台验证。

`-Replace` 仅在新任务注册成功后停用旧 `SEO-Content-Text-Bilibili`，不删除旧任务；若任务正在执行则拒绝替换。不会改动夜间采集、公开来源 GitHub 时间，或整个 `SEO-Content-Night` 任务。原来随采集运行的补处理若仍启用，将受同一个全局处理锁保护。

## 保留与验证

临时媒体和 Cookie 仍在本条结束后清理；模型、登录资料与日志保留。拒绝结果的纯文字/时间段备份在 `C:\trend-collector-data\transcripts\rejected-results`，仅异常时产生，用于人工排查，不是公开接口，也不自动重投旧租约。文件包含原文，勿分享或放进 Git；Windows 目录访问权依赖采集账号的现有 ACL。确认恢复后可由操作人员单独整理，不自动扫删历史文件。

测试包括服务端字段诊断、单条回写错误隔离、失败回写停止、访问暂停、来源锁、超过 50 条的 drain、领取时间预算、Windows 任务替换顺序及 PostgreSQL 租约回归。离线测试不证明远程登录或真实视频识别成功；安装后还需查看任务结果和后台完成数量。
