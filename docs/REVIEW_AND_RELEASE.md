# 奇心共享审核与发布检查

Claude 与 Codex 共用本规范。审核请求只产出结果；修复、迁移、提交、Push、部署分别按用户授权执行。没有验证的项目标为“未验证”，不以勾选模板替代证据。

## 开始检查

- 读取 AGENTS.md、CLAUDE.md 和 git status，保留未提交文件。
- 从 package.json、锁文件和已安装包确认实际技术版本，不沿用历史模板版本。
- 明确范围、目标环境、主项目或独立 Worker；不自动访问生产、调用收费服务或重跑采集。
- 每项发现记录文件/行号、触发条件、影响、证据、建议，区分确认问题与推测。角色名称是检查视角，不冒充独立专家已验证。

## 代码、权限与数据

- 核对服务端用户/分组/站点权限与 service-role 使用边界。公开登录和经过专门服务鉴权的接口按各自协议检查，不一律要求用户会话。
- 验证输入类型、长度、URL、查询过滤器和错误处理；不能仅凭用了 SDK 就断言没有注入或越权。
- 大列表应在数据库先筛选、排序、计数、分页，检查翻页与缓存作用域，避免截断后前端过滤。
- 日期遵守 MYT。页面七日窗口、采集来源日期、发现上涨日期、物理数据保留期分别核对。
- 当前竞品明细清理在 scripts/crawl.ts 与 app/api/cron/route.ts 使用 40 天截止值，并受月度归档保护；该说明是导航，后续以对应版本代码为准。不得把它套用于所有表或擅改保留期。
- 修改采集时同步 lib/crawl-rules.ts，并核对独立 Worker 镜像逻辑；不以主仓库测试替代 Worker 验证。

## 数据库发布门槛

`supabase/schema.sql` 是不完整的历史快照，不是当前完整基线、测试库一键初始化脚本或生产发布入口。迁移目录也不保证能从零重建当前数据库；不得对新库或生产盲跑全部文件。

对每次涉及数据库的变更，形成下列记录：

| 项目 | 必须说明 |
| --- | --- |
| 目标 | 测试/生产环境、项目身份、代码提交；不记录密钥 |
| 对象 | 本次涉及表、列、类型、约束、索引、RPC 签名及调用方 |
| 权限 | RLS、策略、GRANT/REVOKE、函数 SECURITY DEFINER/search_path |
| 现状证据 | 已授权的有范围只读元数据或经脱敏、标日期的结构导出；未取得则标未验证 |
| SQL 范围 | 精确列出本次迁移文件、前置依赖、破坏性操作及数据回填范围 |
| 验证 | 隔离库测试、重复执行行为、旧/新代码兼容性；不写生产业务数据做测试 |
| 执行状态 | 已编写、已测试、已获执行授权、已应用、已回读验证，分别记录 |
| 恢复 | 失败停止条件、回退/前滚方案及所需备份；不能保证可逆时明确说明 |

SQL 文件在 Git 中不代表已应用；生产先前已手动应用也不代表可以重复执行。未取得当前结构证据时，发布结论应为“数据库兼容性未验证”，而不是要求执行 schema.sql。

完整基线重建是独立任务，需要经授权取得 schema-only 结构证据、清理敏感元数据，并在空的隔离库演练；本规范更新不代表基线已补全。

## 环境与本地验证

- 按运行位置列变量：网站前端、网站服务端、GitHub Worker、本机浏览器/转写、本地 Agent。只配置该环境真正需要的变量，禁止将本机全部 .env 上传 Vercel。
- 服务端密钥不加 NEXT_PUBLIC_；本机开发凭证必须属于测试环境。不得输出密钥值。
- 按改动选择 lint、离线测试、类型检查、构建；构建和浏览器验证先核对测试凭证。不要为了检查自动安装/升级全局工具或 Worker 依赖。
- 性能报告只引用实测数字及条件；未实测时说明待测方法，不虚构毫秒数、查询计划或优化收益。
- 界面验证现有后台的桌面、窄屏、键盘、空态和错误态；不恢复页面设计器。历史迁移与退役数据清理测试保留。

## 发布判定

- 检查本次涉及对象与权限、测试结果、配置范围、失败恢复方案。
- 未授权时不 commit、push、触发 workflow、部署或执行迁移。
- 报告分别给出代码检查、本地测试、数据库适配、已推送、已部署、生产验证状态。
- 线上验证必须对应具体版本、来源日期和运行记录，不能以历史测试或任务退出码代替业务成功。
