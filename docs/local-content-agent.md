# 奇心本地内容研究 Agent：第一阶段

先建立 Agent 的职责、任务入口、受限工具循环、执行记录与人工反馈，再逐步接上采集和改写工具。不是先写一篇“小红书”当成完整系统。

## 已具备

- 身份与边界：内容研究助手，仅供负责人本地试用。
- 任务生命周期：排队 → 运行 → 需要资料 / 待审核 / 阻塞 / 失败 → 人工通过或拒绝。人工通过不代表已发布。
- 工具：`memory.search`、`materials.list`、`materials.read`。Agent 自己选择需要的工具，由宿主校验并执行；最多 5 轮、总计约 5 分钟，不自动无限重试。
- 规则记忆：只有明确确认的偏好才进入本地规则。模型输出与审核反馈不会自动改写规则。这是积累规则，不是微调模型。
- 记录：每个任务有 `job.json`、追加的 `events.jsonl` 和成功形成结果后的 `result.md`。
- 输入：读取你明确指定的本地 md/txt/json 或奇心资料包，不扫描项目、数据库或浏览器。最多 8 份，每份 12,000 字符；拒绝常见凭证文件和令牌格式，但仍须人工确认资料已脱敏。

## 奇心现有资料：负责人只读导出

除手动文字资料外，现已支持通过 --materials 导入奇心资料包，仍不扫描项目、数据库或浏览器。最多 8 份，每份 12,000 字符。

本批新增代码尚须提交及部署后才可在正式站访问；不代表当前站点已经开放此接口。在已登录的奇心同源浏览器中访问：

    /api/content-agent/materials?ids=内容发现UUID1,内容发现UUID2

接口只允许活跃的项目负责人账号（super 且 isOwner），其他管理员、组长和组员不能使用。每次必须明确选择 1 至 8 个不重复的记录编号；没有“导出全部”，不读取分组私有提交，不接收模型指定的表、用户或任意查询。编号可由现有内容列表响应取得；本批尚无选择资料的页面按钮。

导出包优先使用已成功保存的字幕，其次使用已保存文章正文，最后退回明确标记的列表摘要。文字查询报错会失败，不会伪装成没有正文。自动字幕／本地识别可能有错字，需人工核对；超过单份 12,000 字符时明确标记为节选，不修改数据库原文。来源的发布时间、首次采集时间、文字更新时间分别保留。链接只保留受支持来源的公开标识参数，去掉追踪和常见分享令牌。

接口不调用模型、不补采、不新增表、不写生产库；响应不缓存。服务端权限检查是导出边界，JSON 文件自身不是登录证明，也不是官方真实性认证。资料导出后应由负责人妥善保管，不要提交进 Git。

将下载文件保存在被 Git 忽略的 .content-agent 目录，然后创建任务：

    npm.cmd run agent -- new --mode plan --task "检查这批资料能支撑什么内容，还缺什么，不生成文章" --materials ".content-agent\qixin-agent-materials.json"

检查后若决定试写，可另建 --mode draft 任务。--materials 暂不与 --reference 混用，以避免来源编号冲突；资料包不能通过普通 --reference 悄悄扁平化。创建任务仍不调用模型，只有明确运行 run 才调用。

来源信息保存在 job.json、show 输出及成功结果的 result.md 中。模型只能引用实际读取过的资料；摘要可用于规划选题，不能单独支撑可审核草稿。这些检查不等于已经自动核实所有事实或重复率。

## 尚未具备

自动采集、百度实时查询、网页登录、验证码处理、自动入库、团队共享 AI 后端、全天定时、自动发布均未接通。不要把本地 Agent 框架当成这些功能已经完成。

第一阶段没有页面入口。先在本机验证 Agent 执行和记录，之后再决定奇心工作台如何创建任务、由哪台机器领取。

## 费用与凭证边界

使用本机 **ChatGPT 登录的 Codex CLI**，消耗当前账号的 Codex 可用额度，不承诺无限或始终可用。脚本强制 `forced_login_method="chatgpt"`，移除传给模型进程的 API Key、Supabase 等业务环境变量；认证失败或额度不足即停止，不自动切换收费 API。

只使用正常的 `codex login`，不复制或导出 `auth.json`。不把个人登录开放为公共或团队共用接口。

模型进程在临时工作目录运行，忽略用户配置，关闭命令、连接器、外部搜索、Hooks 和子 Agent，使用只读权限。宿主保留的工具也只能查询本地已确认规则、阅读本次明确提供的材料。电脑级安全管理策略仍可额外限制或阻止执行；遇到错误不会降低安全等级。

参考：[OpenAI 非交互运行文档](https://learn.chatgpt.com/docs/non-interactive-mode)、[认证方式](https://learn.chatgpt.com/docs/auth)、[配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)。如果以后考虑将 ChatGPT 计划接入托管应用，需要另外确认资格与适用范围，不能把本机登录直接当作奇心的通用 API。

## 使用

在项目目录执行。Node 版本与现有项目要求一致，并先安装 Codex。

```powershell
codex login
npm.cmd run agent -- init
npm.cmd run agent -- status
```

若 Windows 只找到 npm 的 `.cmd` 包装器而无法启动，安装官方原生 CLI，或将 `QIXIN_CODEX_EXECUTABLE` 设置为你已安装的 `codex.exe` 完整路径；不要配置任意外部脚本。

新增一个任务（不会立即调用模型），然后用返回的 UUID 运行：

```powershell
npm.cmd run agent -- new --task "检查你目前能做什么、不能做什么，列出接通自动采集与改写所需的第一步。不要实际抓取或发布。"
npm.cmd run agent -- run --id "这里填返回的UUID"
npm.cmd run agent -- show --id "这里填返回的UUID"
```

任务默认 `--mode plan`，只制定计划；要进入草稿模式需明确加 `--mode draft`。提供资料时，在 `new` 命令加 `--reference "C:\path\facts.md"`。草稿模式未提供材料时应明确要求补充资料，不应编造文章。规划“以后如何改写”不会被误当成立即生成文章。

只有你确认后才保存规则或审核结果：

```powershell
npm.cmd run agent -- remember --text "软件产品标题不要把下载当作名称的一部分" --confirm
npm.cmd run agent -- review --id "这里填返回的UUID" --decision approved --text "已人工核对，仍不自动发布"
```

数据位于项目下 `.content-agent`，已加入 Git 忽略。无需开启 Vercel 长任务或新增 API 密钥；脚本每次只运行指定任务，结束后退出。采集电脑尚未安装或配置本功能时，不会自动在那台电脑运行。

锁文件用于阻止同一任务并发执行。进程异常终止后若锁仍在，先确认原进程已结束再人工处理指定锁；程序不会抢占或自动重复执行旧任务。
