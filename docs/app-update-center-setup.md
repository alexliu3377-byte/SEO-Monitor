# 应用更新中心：v4.0.0 超管实验

这一阶段先在正式网站建立一个独立的实验后台，用来登记应用和公开更新页面、运行 GitHub Actions 抓取、人工审核结果并导出 CSV。它不会下载或保存 APK、安装包、图片和视频。

## 1. 建立数据库

在 Supabase SQL Editor 运行：

`supabase/migrations/20260910_app_update_center_foundation.sql`

成功后不需要新增 Supabase 密钥。GitHub Actions 继续使用项目已有的：

- `NEXT_PUBLIC_SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`

## 2. 部署网站

推送代码并等待 Vercel 部署完成。只有角色为 `super` 的账号会在原系统侧边栏看到“进入应用更新中心”。组员和管理员没有入口，直接访问页面或 API 也会被拒绝。

## 3. 登记应用

### 批量导入 App Store（推荐先测试）

进入“应用更新中心”，点击“批量导入 App Store”：

1. 选择需要观察的商店地区。
2. 不知道 Apple ID 时，直接点击“补全免费榜 100 个”或“补全付费榜 100 个”。系统会先读取 Apple 公开榜单，再通过 Lookup API 补齐资料。
3. 有指定应用时，仍可每行粘贴一个 App Store 链接或数字应用 ID，单次最多 100 个。
4. 导入会直接建立监控清单，并把当前版本、更新日志、发布日期和包大小放进“待审核”；重复应用和重复版本不会重复创建。

App Store 来源在抓取时使用专用接口读取版本号、更新日志、发布日期、包大小和商店链接，不依赖商店网页 CSS。

### 自动持续扩展 App Store 目录

`.github/workflows/app-store-discovery.yml` 每天会自动执行一次：

1. 每天在中国大陆、香港、台湾、马来西亚、新加坡、美国和日本之间轮换一个商店地区。
2. 读取该地区免费榜和付费榜前 100 名。
3. 每天轮换 12 个搜索词，每个词最多读取 200 个结果；默认一半用于普通应用，一半用于游戏。游戏词库覆盖手游、新游戏、独立游戏、角色扮演、策略、卡牌、射击、模拟经营、休闲、动作、冒险、生存等类别，并用 Apple 返回的 Games 分类再次校验，避免普通应用混入游戏结果。
4. 按 Bundle ID 去重；已存在的应用和版本只更新时间，不会重复建立。
5. 每次 Apple 搜索请求间隔 4 秒，保持低频。也可在页面点击“目录扩展任务”，手动指定地区、本轮词数以及 `mixed`（应用和游戏）、`games`（只抓游戏）或 `apps`（只抓应用）模式。

这套方式会持续增加目录，但不能声称等同于完整 App Store。真正的完整目录需要 Apple 面向合作方提供的批量目录数据权限。

### 单个应用或其他公开页面

进入“应用更新中心”，点击“新增应用”，填写：

- 应用名称和平台
- 包名或应用标识（不知道可以先留空）
- 来源名称和类型
- 一个不需要登录即可打开的公开更新页面 URL

同一应用可以添加多个来源。第一轮建议只登记 1 至 3 个你熟悉的应用，先比较官方网站、应用商店或下载站中哪一种页面最稳定。

## 4. 手动运行抓取

点击页面右上角“打开抓取任务”，进入 GitHub Actions 的 `App update crawl`：

1. 点击 `Run workflow`。
2. `app_id` 留空会检查所有启用来源；填写页面中的应用 UUID 时只检查一个应用。
3. `limit` 是本轮最多检查多少个来源，实验初期保留默认值即可。
4. 任务结束后回到应用更新中心刷新页面。

抓到的新版本默认进入“待审核”。确认版本号和更新日志后点击“通过”，它才会成为该应用当前认可的最新版本；错误资料可以“忽略”。

## 5. 导出资料

在更新记录中勾选需要的版本，再点击“导出”。单次最多导出 200 条 UTF-8 CSV，可直接用 Excel 打开。

## 当前限制

- 各网站页面结构不同，通用识别不可能一次覆盖全部来源。
- 页面没有公开更新日志、内容依赖登录或完全由复杂脚本生成时，可能识别失败。
- 当前不自动定时运行；先通过手动任务验证来源稳定性和识别准确率。
- 当前不抓取安装包本体，也不承诺下载链接长期有效。
- App Store 可以从所选地区的免费榜或付费榜自动补全前 100 名，也可导入已知链接或 ID；它不是完整商店目录，不同地区的榜单和版本资料可能不同。
- Google Play 和 TapTap 目前仍走通用公开网页识别，尚未加入批量导入和平台专用解析器。
- 运行失败时先看“抓取记录”和来源错误；稳定后再为常用站点增加专用解析规则。
